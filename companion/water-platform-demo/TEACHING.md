# 教师资源：核心教学路线与验收证据

面向任课教师。三件事：这门课的核心路线怎么走、每次课收什么、学生卡住时该往回指哪里。

学时按 56 学时排（见教材前言的学时表），讲授与实验约 30 : 26。
教材每个编号小节都标了层次——**核心 / 指导实践 / 拓展**。
核心理论不以前置拓展阅读为条件；指导实践使用骨架，仍按课程成果收取实验。课时调整时保留核心失败例。

## 一、核心教学路线

一条线索：**一次观测从传感器到值班员屏幕，中间每一步是谁做的、出错时怎么查。**
第1章把这条线走一遍不写代码，第4–8章逐段把它实现出来。

| 段落 | 章节核心小节 | 阶段包 | 学时（讲/实验） |
|---|---|---|---|
| 看懂一次请求 | 1.2.1 | S0 | 2 / 0 |
| 把含糊需求写成验收条件 | 2.5、2.6 | — | 3 / 2 |
| 划分模块与接口 | 3.1–3.3 | — | 3 / 2 |
| 做出会动的页面 | 4.2–4.4 | S1 | 4 / 3 |
| 请求状态与Vue指导实践 | 4.5–4.7（尤其 4.5.4） | S2 | 3 / 4 |
| 写出自己的接口 | 5.2、5.4、5.5、5.6 | S3 | 7 / 7 |
| 把测点放进三维场景 | 6.1 | S4 | 3 / 2 |
| 曲线与场景联动 | 7.2–7.4 | S5 | 3 / 2 |
| 质量、预警与闭环 | 8.3、8.4、8.6 | S6 | 2 / 3 |
| 回顾与个人答辩 | 9.1 | — | 0 / 1 |
| 合计 | 与前言学时表一致 | — | 30 / 26 |

课时是建议值，以试教实测校准。**第5章是最容易超时的一章**：
学生第一次同时面对 Java 工程结构、注解和 HTTP 语义。
把附录B 的 P2 单元（Java 源文件 → Maven 工程 → Spring 注解）放在 5.1 之前当预备课，
比在 5.2 现场解释注解要省时间。

## 二、课程成果与验收证据

教材 9.1 节的 O1–O7 核对表在这里配上可收的东西。
O1–O3提交解释、模型或可判定的需求及一个反例；O4–O7提交**可运行结果和失败记录**。阶段脚本只能证明其覆盖的行为，个人解释与未覆盖的任务另行评分。

| 成果 | 学生要交什么 | 怎么判 |
|---|---|---|
| O1 解释一次请求的完整过程 | 对照 `S0-demo-record.md` 说明六个环节 | 能指出页面无数据时先看哪一环 |

## 三、学生最常卡住的六处

以下按教学顺序安排为故障练习，实际频率与完成时间由本次课堂记录，不预设试教结果。

**1. 端口被占用。** 教学接口和 Spring Boot 都用 8080。
学生同时开着两个，后启动的那个报 `Port 8080 was already in use`，
但很多人只看到“启动失败”就重装环境。→ 附录B P0 单元，或 S3 那一步的运行说明。

**2. 快速切换测点时旧数据覆盖新数据。** 这是第4章的核心故障单元，
不是边角情况：手速稍快就能复现。让学生比较延时与请求归属校验的差别，
本书实现采用 `AbortController` 加递增序号。→ 4.5.4。

**3. 时间参数里的加号。** `from=2026-07-01T00:00:00+08:00` 直接放进地址栏，
`+` 被当成空格，服务端 400 但错误体不是契约格式。
它说明“统一错误体”不是在控制器里加几个方法就能做到的。→ 5.2.2 与 5.5。

**4. 三维场景黑屏。** 三种原因：没加光源、相机在物体内部、忘了渲染循环。
让学生各制造一次比讲三遍有效。→ 6.1.1 的排查表。

**5. 把 suspect 数据送进评分。** 系统连续产生蓝色事件，值班员关掉推送，
真正的黄色趋势反而没人确认。这是第8章的两个坑之一。→ 8.4 与 `classify.js`。

**6. 把“未评估”显示成“无预警”。** 缺测被画成绿色，看起来一切正常。
`evaluable` 与 `level` 必须是两个维度。→ 同上。

## 四、实验课的收法

每次实验课收两样：**能跑的东西** + **一条失败记录**。
失败记录写四行就够——现象、原因、处理、验证。

不建议按代码行数或页面美观度打分。判断一段代码写得好不好，
需要同时看正常路径和异常路径：
界面告诉了用户什么、日志里留下了什么、下一个人能不能照着复现。

阶段包里的自动化脚本可以直接当评分依据：

```bash
node teaching-api/contract-check.mjs  http://localhost:8080 --stage=lesson52   # O5起点；终点另用 --stage=full
node teaching-api/closeloop-check.mjs http://localhost:8080                    # O7
cd frontend
npm test                                                       # O4、O6
```

退出码为0表示脚本覆盖的检查通过；还应收取实验记录与个人解释。S3起点没有登录，完整页面替换须等终点契约通过；S2详情路由需要学生实现，现有核心页测试不覆盖它。

## 五、环境准备清单

开课前在机房验证一遍，避免第一次实验课花在装环境上。

| 需要 | 用于 | 验证命令 |
|---|---|---|
| Node 20+ | S1–S2、S4–S6、教学接口 | `node --version` |
| JDK 17 | S3 | `java -version` |
| Maven | S3 | `mvn -v` |
| Docker + Compose | S3 终点、S6 终点 | `docker compose version` |
| 浏览器开发者工具 | 全程 | 能打开“网络”与“元素”面板 |

S1、S2、S4、S5 只需要 Node 与浏览器。**数据库和 Docker 到第5章后半才需要**，
不必在开课第一周就要求所有学生装好——那会挡住本来可以顺利完成的前四周。
