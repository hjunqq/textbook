# 5.5.4 数据库设计

## 数据库设计流程

1. **需求分析**：明确数据存储和使用需求
2. **概念设计**：创建实体关系图(ER图)
3. **逻辑设计**：转换为关系模型或NoSQL数据模型
4. **物理设计**：确定存储结构、索引策略等
5. **优化调整**：根据性能测试进行优化
6. **维护更新**：持续调整以适应需求变化

## 关系型数据库设计原则

1. **数据规范化**
   - 第一范式(1NF)：属性不可分割
   - 第二范式(2NF)：非主属性完全依赖主键
   - 第三范式(3NF)：非主属性不依赖其他非主属性
   - BC范式(BCNF)：主属性不依赖其他非主属性

2. **实体关系建模**
   - 一对一关系
   - 一对多关系
   - 多对多关系

3. **设计技巧**
   - 使用合理的命名规范
   - 选择适当的数据类型
   - 合理设置默认值和约束
   - 考虑数据完整性和一致性

## NoSQL数据库设计原则

1. **数据反规范化**
   - 优化查询性能而非存储空间
   - 根据查询模式组织数据

2. **文档设计**
   - 嵌入vs引用：根据查询和更新频率决定
   - 避免过深的嵌套
   - 考虑文档大小限制

3. **关键考虑因素**
   - 读写比例
   - 查询模式
   - 数据增长预期
   - 数据一致性要求

## 数据安全设计

1. **访问控制**
   - 基于角色的访问控制(RBAC)
   - 最小权限原则
   - 敏感数据访问审计

2. **数据加密**
   - 传输加密(TLS/SSL)
   - 数据存储加密
   - 敏感字段加密

3. **备份与恢复**
   - 定期全量备份
   - 增量备份
   - 点in-time恢复能力
