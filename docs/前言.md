# 前言

!!! note "说明"

    **写给翻开这本书的你**

    如果你是一名水利工程专业的大三学生，你可能正在思考一个问题：学水利的，为什么要学写代码？

    答案就藏在你身边。打开手机查看天气预报中的降水预警，浏览新闻里水库实时水位的三维动态图，或者在实习中看到监测站大屏上跳动的数据曲线——这些背后，都是软件平台在支撑。今天的水利工程师，不仅要懂水力学和结构力学，还需要理解这些平台是如何设计和构建的。这正是本书希望带给你的能力。

## 为什么写这本书

近年来，“数字孪生水利”“智慧水利”已从政策文件走进了工程实践。《国家水网建设规划纲要》明确提出“建设数字孪生水网”<sup>[[1]](references.md#ref1)</sup>，各流域管理机构和水利工程单位对兼具水利专业背景和软件开发能力的复合型人才需求急剧增长。

然而在教学中，我们面临一个尴尬的现实：计算机专业的软件工程教材讲得深，但案例全是电商、社交，与水利毫无关系；水利信息化教材介绍了不少概念，但很少教学生怎样动手搭建一个真正能跑起来的平台。本教材的初衷，就是填补这个空白——用水利工程的真实场景来串联软件开发的完整流程，让你学到的每一行代码都与专业相关。

## 这本书讲什么

全书九章，按照**“打基础 $\rightarrow$ 学技术 $\rightarrow$ 做项目”**的思路组织，分为三个部分。

!!! tip "提示"

    **第一部分基础篇（第1–3章）**

    从智慧水利的概念出发，建立对平台整体架构的认知。然后进入软件工程的核心内容：需求怎么分析、系统怎么设计、架构怎么选型。这部分是后续所有开发工作的理论根基。

!!! tip "提示"

    **第二部分技术篇（第4–7章）**

    四章对应平台开发与可视化表达的核心技术链：

    - **前端**（第4章）：HTML/CSS/JavaScript基础，Vue.js框架开发，重点是如何构建水情数据展示界面

    - **后端**（第5章）：Spring Boot框架（Java 17 / Jakarta EE），RESTful API设计、JPA持久化、Spring Security与消息队列；Python生态（Flask/FastAPI）作扩展阅读简介

    - **三维场景**（第6章）：WebGL/Three.js三维渲染，GIS地图服务，BIM建模与数字孪生技术

    - **观测数据展示**（第7章）：监测数据面向三维场景的组织、可视化表达、交互与联动

    每个技术点都围绕水利监测平台的实际需求展开，代码示例均取自水利业务场景。

!!! tip "提示"

    **第三部分应用篇（第8–9章）**

    前两部分学到的方法与技术，在这里汇聚成完整的项目实践。第8章以**水利工程安全监测平台**为起点，从业务需求、总体架构和数据模型出发，完成前后端、三维场景、智能分析、部署与验收的完整链路；并在8.5节进一步演进到数字孪生水利平台，以流域、水网和工程三类入口贯通“预报、预警、预演、预案”。第9章回顾全书，并给出技术展望与后续学习指引。

## 怎么使用这本书

**先说最重要的一条：一定要动手写代码。**

软件开发不是看会的，是写会的。每章末尾都有思考题和练习题，思考题帮你梳理概念，练习题要求你实际编码。请认真对待它们。

以下是几条具体建议：

1.  **按顺序学习。**各章内容前后衔接，第4–7章的开发与可视化技术依赖第1–3章的方法基础，第8章的综合实践又建立在第4–7章的技术基础上。不建议跳章阅读。

2.  **搭建本地开发环境。**学习前端章节时，准备好Node.js和VS Code；学习后端章节时，以Java 17和Spring Boot为主线安装开发环境，Python环境用于扩展阅读。在自己的电脑上运行书中的示例，比看十遍书都有效。

3.  **组队做课程设计。**如果条件允许，建议3–4人组成开发小组，分工协作完成一个小型水利监测平台。前端、后端、三维场景各有分工，在协作中体会真实项目的开发流程。

4.  **善用搜索引擎和技术社区。**书中不可能涵盖所有细节。遇到问题时，学会查阅官方文档、在Stack Overflow或CSDN上搜索解决方案，这本身就是软件工程师的核心技能之一。

**配套工程的定位。**

`companion/water-platform-demo/`提供的是一条**最小可运行闭环**：登录认证、测点与观测查询、消息消费入库、一条命令启动和前后端各自的冒烟测试，用来证明全书技术栈能够协同工作，并作为练习的起点仓库。它不逐条收录书中203个代码清单——清单服务于讲解，仓库服务于运行，两者以文件路径和章节号互相索引（见仓库`MAPPING.md`）。读者应把书中清单视为“把仓库改造成完整平台”的施工图，而不是期待仓库已经包含成品。

**代码仓库结构。**

配套代码的根目录为`companion/``water-platform-``demo/`（仓库提交`f71b52a`）。`frontend/`的可运行入口是`package.json`、`src/``main.js`、`src/router/``index.js`、`src/stores/``monitoring.js`、`src/utils/``request.js`和`src/components/``MonitoringDashboard.vue`，并配有`vite.config.js`、`Dockerfile`和`nginx.conf`；`backend/`包含`pom.xml`、`src/main/java/``edu/example/``qingyuan/`下的实体、Repository、服务、JWT 过滤器和安全配置，以及`application.yml`和`Dockerfile`；`db/`包含`001_init.sql`与`load-s3-data.sql`；根目录的`docker-compose.yml`负责编排前端、后端、PostgreSQL、Redis和Kafka，`secrets/`只提交`*.example`模板。目录中的每个服务都提供配置样例和健康检查说明，学生可以先运行最小链路，再逐个替换为章节中的实现。

**示例数据集。**

`companion/datasets/`（仓库提交`4fed08e`）由`generate.py`生成，固定随机种子为`20260807`。`stations.csv/json`含28个测点元数据，字段为`asset_id`、`asset_type`、`display_name`、单位、经纬度、`elevation_m`、量程、精度、阈值和投运日期；`water_level.csv`含3个库水位测点各1,200条、5分钟间隔的观测；`rainfall.csv`含5个雨量测点各288条，`piezometer.csv`含12个渗压测点各288条；8个位移测点当前仅提供`stations`中的元数据与阈值，其观测序列留作第7章练习用`generate.py`扩展生成。三类已生成观测共同使用`asset_id`、`occurred_at`、`version`、`event_id`、`value`、`unit`、`quality`和`source`字段；`warnings.json`含蓝、黄、橙、红、无预警（NONE）与未评估样例。质量码只取`valid`、`suspect`、`missing`，文件中的缺测、超量程和跳变记录均保留原因。使用前应先阅读README中的字段说明，确认时间采用ISO 8601、时区采用UTC+8，并在报告中注明数据版本。

## 适用对象

**适用读者**

本书以水利工程及相关专业高年级本科生为主要读者，兼顾研究生，以及有志于从事水利信息化、智慧水利平台开发的技术人员。

**先修知识**

学习本书前，你需要具备以下基础：

- 至少学过一门编程语言（C、Python或Java均可）

- 了解基本的数据结构概念（数组、链表、树等）

- 对水利工程有初步认识（水力学、水文学等先修课程）

- 了解基本的数据库概念与SQL语言（推荐但不强制）
