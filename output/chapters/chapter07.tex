\chapter{三维场景的观测数据展示}

\paragraph*{学习目标}

通过本章学习，学生应能够：

\begin{enumerate}
\item 说明观测数据进入图表和三维场景前所需的字段、质量码与时间窗口；
\item 使用Apache ECharts建立可增量更新的监测曲线，并设计图表与三维对象的联动；
\item 按CGCS2000、高斯--克吕格平面坐标和场景局部坐标的链路定位监测点；
\item 实现射线拾取、触控长按、状态编码、LOD与聚合，并正确处理像素和世界单位；
\item 围绕一个水库监测案例形成可复现的三维观测数据展示方案。
\end{enumerate}

\paragraph*{引言}

第6章解决三维场景如何构建，本章进一步回答“监测数据怎样在场景中被准确、及时且可解释地展示”。数据接入、持久化和跨服务消息属于第5章的后端职责；本章只保留可视化所需的数据准备，重点讨论图表、空间定位、状态表达和人机交互。

本章使用“清源水库”作为教学虚构案例。坝高设为52\,m，正常蓄水位168.0\,m；平台接入12个渗压测点、8个位移测点、3个库水位测点和5个雨量测点，共28个观测点，另展示6个采集网关的在线状态。所有数值仅用于教学练习，不代表真实工程。

\subsection{时间窗口、降采样与缺测}

实时曲线通常采用滑动时间窗口，只保留最近若干分钟或小时；历史查询则按屏幕宽度和时间跨度选择聚合粒度。后端应提供原始与聚合数据接口，前端不应一次下载多年高频数据再自行压缩。

当历史点数远大于横向像素数时，可使用Largest-Triangle-Three-Buckets（LTTB）降采样。算法保留首尾点，把中间序列分桶；在每个桶中，选择与前一已选点和下一桶平均点构成三角形面积最大的点，从而尽量保留峰谷与转折\cite{steinarsson2013lttb}。对候选点$B$，面积为

\[
A=\frac{1}{2}\left|
(x_A-x_C)(y_B-y_A)-(x_A-x_B)(y_C-y_A)
\right|.
\]

LTTB适合视觉浏览，不应用其结果替代原始数据计算统计指标。缺测区间应断线或用明确的虚线/阴影表示；插值只用于允许插值的连续物理量，并在提示中给出原始与插值标记。降雨累计量、设备开关状态等数据不能套用相同插值规则。

\section{图表与实时联动}\label{sec:data-chart-display}

\subsection{图表选型与视觉编码}

折线图适合连续过程，柱状图适合分时段雨量，散点图适合比较两个变量，箱线图适合展示分布，仪表盘只宜表达少量当前状态。同一页面不应为了“丰富”而堆叠图形；应从读者要完成的比较、定位或判断任务出发。

本书以Apache ECharts为图表主线。ECharts最初由百度团队开源，2018年捐赠给Apache软件基金会，2021年从孵化器毕业为顶级项目，现由ASF社区维护并持续发布版本\cite{apacheECharts}。了解这段沿革有助于区分项目起源与当前治理主体。Chart.js可用于轻量页面，Three.js负责三维场景；二者通过对象标识和时间范围与图表协同。

\subsection{可运行的实时曲线}

ECharts实例必须先设置完整初始配置，再进行增量更新。下面示例把最近300个水位点保留在前端；更长时间范围应重新请求聚合数据。

\label{lst:ch07-chart}
\begin{lstlisting}[language=JavaScript,breaklines=true,caption={图表数据转换}]
const chart = echarts.init(document.querySelector('#level'));
chart.setOption({
  animation: false,
  xAxis: { type: 'time' },
  yAxis: { type: 'value', name: 'm' },
  series: [{ id: 'level', type: 'line',
    showSymbol: false, data: [] }]
});

function appendReading(reading) {
  const series = chart.getOption().series[0];
  const next = [...series.data,
    [reading.occurredAt, reading.value]].slice(-300);
  chart.setOption({ series: [{ id: 'level', data: next }] });
}
\end{lstlisting}

代码先调用\texttt{setOption}建立坐标轴和带稳定ID的序列，因此后续局部配置能找到更新目标。生产代码还应验证单位和质量码，并在组件卸载时解除消息订阅、窗口事件与图表实例。

\subsection{图表与三维对象联动}

用户点击图表上的异常点时，联动控制器读取\texttt{assetId}和时间，定位场景中的测点并打开同一时刻的详情；反向点击三维测点时，曲线切换到对应监测项并标出当前事件。联动状态应放在页面状态管理中，不要通过运行时给图表对象“动态挂方法”。

交互事件可能很密集。指针移动使用节流，时间范围查询使用防抖，告警确认则不得被节流丢弃。触控长按必须在抬起或取消时清理定时器：

\label{lst:ch07-vue-watch}
\begin{lstlisting}[language=JavaScript,caption={实时观测联动}]
let longPressTimer = null;
const delayMs = 600;

canvas.addEventListener('pointerdown', event => {
  longPressTimer = setTimeout(
    () => openPointMenu(event), delayMs);
});

function cancelLongPress() {
  if (longPressTimer !== null) clearTimeout(longPressTimer);
  longPressTimer = null;
}
['pointerup', 'pointercancel', 'pointerleave']
  .forEach(type => canvas.addEventListener(type, cancelLongPress));
\end{lstlisting}

短按在\texttt{pointerup}前已经取消定时器，不会误触发长按；\texttt{pointercancel}覆盖系统手势或窗口切换导致的中断。

\subsection{响应式与异常状态}

大屏可同时呈现工程总览、关键曲线和告警列表；桌面端优先支持查询与研判；移动端优先显示待办、定位和确认。屏幕缩小时应调整信息优先级，而不是简单等比缩放全部组件。

无数据、加载中、权限不足、接口失败和数据质量可疑是五种不同状态。界面应分别给出原因与可执行动作，例如重试、切换时间范围、申请权限或查看质量详情。空白图表不能让用户猜测是“确实没有数据”还是“接口已经失败”。

工程场景不宜直接使用数十万米的平面坐标作为单精度顶点。应选择经测量确认的局部原点$(E_0,N_0,H_0)$，再映射为

\[
x=E-E_0,\qquad y=H-H_0,\qquad z=-(N-N_0).
\]

负号来自Three.js常用的相机与地面坐标约定，项目也可采用其他轴向，但数据、模型和交互必须统一。

\label{lst:ch07-coordinate-transform}
\begin{lstlisting}[language=JavaScript,breaklines=true,caption={坐标与单位转换}]
const cgcs2000 = '+proj=longlat +ellps=GRS80 +no_defs';
const gauss = '+proj=tmerc +lat_0=0 +lon_0=117 '
  + '+k=1 +x_0=500000 +y_0=0 +ellps=GRS80 +units=m';

const [east, north] = proj4(
  cgcs2000, gauss, [longitude, latitude]);
const world = {
  x: east - origin.east,
  y: normalHeight - origin.height,
  z: -(north - origin.north)
};
\end{lstlisting}

中央经线\texttt{lon\_0}必须按工程所在投影带确定，不能照抄示例。UTM同属横轴墨卡托投影体系，适合某些国际数据交换，但不是国内水利工程坐标的默认主线；输入若为UTM，应先核对带号、半球、基准和元数据，再转换到项目统一坐标。

\subsection{状态编码、LOD与聚合}

清源水库的28个观测点规模较小，可以逐点绘制；流域级场景可能包含成千上万个对象，需要LOD和聚合。近距离显示图标、方向和标签，中距离只显示状态符号，远距离按空间网格或工程对象聚合。LOD阈值应按屏幕占用和交互任务实测，不以固定“米数”套用所有相机。

若希望聚合半径在屏幕上约为$r_{px}$像素，必须先换算成当前深度处的世界长度。透视相机垂直视场角为$\theta$、对象到相机距离为$d$、画布高度为$H_{px}$时，可近似取

\[
r_{world}=\frac{2d\tan(\theta/2)}{H_{px}}\,r_{px}.
\]

然后再用$r_{world}$作为世界坐标网格大小。相机移动或视口变化时重新计算；不能把“20像素”直接写入以米为单位的网格参数。

\subsection{状态变化与渲染更新}

业务状态与数据质量分开编码。对象颜色表示正常、关注、告警或离线，描边/角标表示数据可疑或人工修订。状态更新只修改材质、标签和详情数据，不重复加载模型。

批量更新时先按\texttt{assetId}建立对象索引，再在一帧内合并修改。高频观测值不必全部驱动材质变化；只有跨越状态边界或用户正在查看该对象时才更新三维外观，从而避免无意义的GPU和DOM开销。

\section{监测点互动与拾取技术}\label{sec:monitoring-interaction}

\subsection{射线拾取与安全的向量运算}

屏幕点击首先转换为归一化设备坐标，再由相机生成射线，与场景对象求交。Three.js的\texttt{Raycaster}已经处理常见网格与点对象；拾取器在构造时保存场景引用，并在方法中通过该引用访问可拾取对象，使依赖关系显式、便于测试和复用。

\label{lst:ch07-lod-points}
\begin{lstlisting}[language=JavaScript,caption={LOD监测点聚合}]
class PointPicker {
  constructor(camera, scene, canvas) {
    this.camera = camera;
    this.scene = scene;
    this.canvas = canvas;
    this.raycaster = new THREE.Raycaster();
  }
  pick(clientX, clientY) {
    const rect = this.canvas.getBoundingClientRect();
    const ndc = new THREE.Vector2(
      2 * (clientX - rect.left) / rect.width - 1,
      1 - 2 * (clientY - rect.top) / rect.height);
    this.raycaster.setFromCamera(ndc, this.camera);
    return this.raycaster.intersectObjects(
      this.scene.children, true);
  }
}
\end{lstlisting}

若教学中手工实现M\"oller--Trumbore三角形求交，必须复制向量后再做减法、叉乘和缩放，避免破坏顶点与射线输入：

\label{lst:ch07-raycaster}
\begin{lstlisting}[language=JavaScript,caption={射线拾取器定义}]
function intersectTriangle(origin, direction, a, b, c) {
  const edge1 = b.clone().sub(a);
  const edge2 = c.clone().sub(a);
  const p = direction.clone().cross(edge2);
  const det = edge1.dot(p);
  if (Math.abs(det) < 1e-8) return null;
  const inv = 1 / det;
  const tvec = origin.clone().sub(a);
  const u = tvec.dot(p) * inv;
  if (u < 0 || u > 1) return null;
  const q = tvec.clone().cross(edge1);
  const v = direction.dot(q) * inv;
  if (v < 0 || u + v > 1) return null;
  const t = edge2.dot(q) * inv;
  return t >= 0
    ? origin.clone().add(direction.clone().multiplyScalar(t))
    : null;
}
\end{lstlisting}

\subsection{触控半径与世界单位}

\texttt{raycaster.params.Points.threshold}使用世界单位，不是像素。触控目标希望具有20像素左右的可点范围时，先按相机距离和视场角换算：

\label{lst:ch07-picker}
\begin{lstlisting}[language=JavaScript,caption={拾取结果与业务对象绑定}]
function pixelsToWorld(px, distance, fovRad, heightPx) {
  return 2 * distance * Math.tan(fovRad / 2)
    * px / heightPx;
}
const pickingRadiusWorld = pixelsToWorld(
  20, distanceToPoint, THREE.MathUtils.degToRad(camera.fov),
  canvas.clientHeight);
raycaster.params.Points.threshold = pickingRadiusWorld;
\end{lstlisting}

这里的\texttt{pickingRadiusWorld}已定义且量纲与场景一致。对象深度变化明显时，应按候选对象距离计算或改用屏幕空间命中测试；不能把固定像素半径直接当成米。

\subsection{信息面板与渐进披露}

第一次点击显示测点名称、当前值、单位、质量码、状态和更新时间；展开详情后显示短期曲线、阈值版本和相邻测点；进一步进入专题页才加载多年历史、模型结果和处置记录。渐进披露减少遮挡，也让移动端保留足够大的触控区域。

拾取到多个重叠对象时，优先按交点距离排序，但不能直接替用户决定业务对象。界面可列出候选项，或先选择聚合簇再下钻。无权限的敏感属性不进入浏览器载荷，仅显示允许公开的概要。

\subsection{案例联调与验收}

清源水库案例至少验证以下路径：

\begin{enumerate}
\item 点击渗压曲线的异常点，场景定位到\texttt{DAM-A-PZ-07}并显示同一事件时间；
\item 点击雨量站，图表切换到该站24小时雨量并保留工程时间窗；
\item 缩小场景后28个观测点按坝区聚合，聚合符号显示数量和最高风险；
\item 移动端短按只打开概要，长按600\,ms打开操作菜单，取消手势不触发长按；
\item 缺测、可疑和离线分别显示，且详情中可追溯质量码与来源。
\end{enumerate}

验收记录应包含输入数据版本、浏览器与设备、操作步骤、预期结果、实际结果和截图编号。这样，三维展示不只是一次演示，而是可以复现和回归测试的课程成果。

\section*{小结}

本章把观测记录沿“质量与时间校验—图表表达—空间定位—拾取交互”链路映射到三维场景。可视化数据准备只保留前端所需契约，后台数据工程仍归第5章；坐标主线与第6章一致，采用CGCS2000和高斯--克吕格坐标，再转换到以米为常用单位的局部场景坐标。Apache ECharts负责趋势与统计，Three.js负责空间与状态，联动控制器以对象标识和时间窗保持两者一致。

\section*{思考题与练习题}

\begin{enumerate}
\item[\textbf{客观题}]
\item 场景局部坐标的常用单位是像素。（判断：对／错）

\item LTTB降采样结果可以替代原始数据计算统计报表。（判断：对／错）
\item 实时ECharts序列在增量更新前应先建立初始配置。（判断：对／错）

\end{enumerate}
