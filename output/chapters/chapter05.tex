\chapter{后端开发技术}

\paragraph*{学习目标}

通过本章学习，学生应能够：
\begin{enumerate}
\item 说明智慧水利后端的职责，设计符合HTTP语义的RESTful API；
\item 使用Spring Boot组织配置、依赖注入、控制器与服务；
\item 使用Jakarta Persistence完成实体映射、Repository访问和事务处理；
\item 使用Spring Security 6与JWT实现基本认证和授权；
\item 区分进程内事件与跨服务消息，并使用消息队列实现可靠解耦；
\item 通过缓存、分页、日志与指标改善服务性能和可运维性。
\end{enumerate}

\paragraph*{引言}

智慧水利后端负责接入监测数据、执行业务规则、维护一致性并向前端提供接口。本章统一采用Java 17、Spring Boot 3.2+、Spring Security 6、Jakarta Persistence 3.1与Jakarta Servlet 6.x；JWT示例按jjwt 0.11+接口编写。分布式事务和领域驱动设计作为选学内容，不作为首次后端课程的前置要求。

\section{后端服务与REST接口概述}

后端位于用户界面与数据资源之间，承担身份校验、业务计算、持久化、审计和系统集成。典型请求链路为“浏览器或设备网关—控制器—应用服务—Repository—数据库”。控制器只处理协议转换和输入校验，业务规则放在服务层，数据访问集中在Repository；若进一步拆分为网络服务，还需显式管理边界、版本和分布式失败\cite{newman2021}。

HTTP方法的基本语义见表\ref{tab:http-methods}。接口设计不仅要返回数据，还要正确使用状态码：创建成功通常返回201，参数无效返回400，未认证返回401，无权限返回403，资源不存在返回404，服务器异常返回500。

本段涉及的字段、职责或条件见表\ref{tab:http-methods}，读者可据此核对取值范围和验收依据。
\begin{table}[htbp]
\centering
\caption{REST接口常用HTTP方法}
\label{tab:http-methods}
\begin{tabular}{lll}
\toprule
方法 & 典型语义 & 水利示例 \\
\midrule
GET & 查询资源 & 查询测站最新水位 \\
POST & 创建资源或触发命令 & 创建告警处置单 \\
PUT & 整体替换资源 & 更新测站完整配置 \\
PATCH & 局部修改资源 & 修改告警状态 \\
DELETE & 删除资源 & 删除尚未发布的规则 \\
\bottomrule
\end{tabular}
\end{table}

资源路径使用名词，例如\texttt{/api/stations/ST-01/readings}；筛选条件放入查询参数，例如\texttt{?from=...\&to=...}。设备协议接入属于边缘网关职责，本章不展开Modbus或MQTT细节。

\section{Spring Boot企业级开发基础}

Spring Boot通过约定、自动配置和Starter依赖减少基础配置。自动配置会依据类路径、配置属性和已有Bean选择合适组件，但开发者仍应理解其条件，避免把“自动”误解为“不可控”。推荐目录如下：

\label{lst:ch05-http}
\begin{lstlisting}[caption={HTTP方法与资源语义}]
src/main/java/com/example/water/
  controller/   # HTTP适配
  service/      # 用例与事务边界
  repository/   # 数据访问
  domain/       # 实体和值对象
  config/       # 安全与基础设施配置
src/main/resources/application.yml
\end{lstlisting}

配置应从代码中分离，并可被环境变量覆盖。密钥不得写入版本库。

\label{lst:ch05-application}
\begin{lstlisting}[caption={Spring Boot应用入口}]
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/water}
    username: ${DB_USER:water_app}
    password: ${DB_PASSWORD}
security:
  jwt:
    secret: ${JWT_SECRET_BASE64}
\end{lstlisting}

依赖注入优先使用构造器，使依赖明确并便于测试。控制器把DTO交给服务，不直接访问数据库。

\label{lst:ch05-query-controller}
\begin{lstlisting}[language=Java,caption={查询接口控制器}]
@RestController
@RequestMapping("/api/stations")
class StationController {
    private final StationQueryService queryService;

    StationController(StationQueryService queryService) {
        this.queryService = queryService;
    }

    @GetMapping("/{id}/latest")
    ReadingResponse latest(@PathVariable String id) {
        return queryService.latest(id);
    }
}
\end{lstlisting}

Spring Boot 3使用\texttt{jakarta.servlet.*}命名空间。旧项目从\texttt{javax.servlet.*}迁移时，应同步检查依赖、过滤器、验证注解和JPA包名。Jakarta Servlet 6.x是本章基线；迁移完成后还应通过编译、集成测试和容器启动检查确认包路径与运行时容器一致。

\section{Jakarta Persistence与事务管理}

\subsection{实体映射与Repository基础}

先建立实体映射与Repository，再讨论事务边界。实体标识应稳定；接口层DTO与持久化实体分离，避免数据库结构直接成为外部契约。

\label{lst:ch05-jpa-entity}
\begin{lstlisting}[language=Java,caption={Jakarta实体映射}]
@Entity
@Table(name = "water_reading")
class WaterReading {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(nullable = false) private String stationId;
    @Column(nullable = false) private double level;
    @Column(nullable = false) private Instant measuredAt;

    protected WaterReading() {}
    WaterReading(String stationId, double level, Instant measuredAt) {
        this.stationId = stationId;
        this.level = level;
        this.measuredAt = measuredAt;
    }
}

interface WaterReadingRepository extends JpaRepository<WaterReading, Long> {
    Optional<WaterReading> findFirstByStationIdOrderByMeasuredAtDesc(String id);
}
\end{lstlisting}

Repository提供基本数据访问，服务层决定一次用例需要哪些读写。查询列表时应分页，避免把多年监测记录一次加载到内存。

\subsection{事务边界与传播}

\texttt{@Transactional}通常标注在公开服务方法上。Spring默认通过代理拦截外部调用；同一Bean内部用\texttt{this.method()}自调用不会经过代理，因此方法上的新事务注解不会生效。需要\texttt{REQUIRES\_NEW}时，应把该职责放到另一Bean。

\label{lst:ch05-repository}
\begin{lstlisting}[language=Java,caption={监测记录仓储接口}]
@Service
class AuditService {
    private final AuditRepository auditRepository;
    AuditService(AuditRepository auditRepository) {
        this.auditRepository = auditRepository;
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void record(String action) {
        auditRepository.save(new AuditLog(action, Instant.now()));
    }
}

@Service
class ReadingCommandService {
    private final WaterReadingRepository repository;
    private final AuditService auditService;

    ReadingCommandService(WaterReadingRepository repository,
            AuditService auditService) {
        this.repository = repository;
        this.auditService = auditService;
    }

    @Transactional
    public void save(WaterReading reading) {
        repository.save(reading);
        auditService.record("SAVE_READING"); // 经另一Bean代理调用
    }
}
\end{lstlisting}

主业务是否应与审计记录使用不同事务，取决于失败语义；不能只为展示传播行为而滥用新事务。首次后端课程重点掌握默认传播、回滚规则和事务边界即可。

\subsection{统计量更新}

增量平均值在已有样本数为$n$、均值为$\bar{x}_n$时加入新值$x$，应计算
\[
  \bar{x}_{n+1}=\frac{\bar{x}_n n+x}{n+1}.
\]
计数和均值必须初始化，并在计算后再更新计数。

\label{lst:ch05-tx-service}
\begin{lstlisting}[language=Java,caption={事务服务边界}]
class WaterDataSummary {
    private long dataCount = 0L;
    private double averageLevel = 0.0;

    public void updateStatistics(double newLevel) {
        averageLevel = (averageLevel * dataCount + newLevel)
                / (dataCount + 1);
        dataCount++;
    }
}
\end{lstlisting}

\begin{tipbox}
选学：跨服务一致性可使用事务消息、Saga或补偿流程；DDD聚合可帮助表达复杂一致性边界。这些方法需要结合业务失败语义、幂等和可观测性学习，不作为本章基础代码的必要组成。
\end{tipbox}

\section{服务层与异常处理}

服务层按用例组织方法，例如“保存监测值”“确认告警”“查询测站详情”。输入DTO先通过Bean Validation完成格式校验，领域规则仍由服务或领域对象校验。统一响应不应把所有结果都包装成HTTP 200；HTTP状态码仍须表达协议层结果。

\label{lst:ch05-exception-handler}
\begin{lstlisting}[language=Java,caption={参数校验异常处理}]
record CreateReadingRequest(
        @NotBlank String stationId,
        @DecimalMin("0.0") @DecimalMax("50.0") double level,
        @NotNull Instant measuredAt) {}

@RestControllerAdvice
class GlobalExceptionHandler {
    @ExceptionHandler(EntityNotFoundException.class)
    ResponseEntity<ProblemDetail> notFound(EntityNotFoundException ex) {
        ProblemDetail problem = ProblemDetail.forStatus(404);
        problem.setTitle("资源不存在");
        problem.setDetail(ex.getMessage());
        return ResponseEntity.status(404).body(problem);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    ResponseEntity<ProblemDetail> invalid(MethodArgumentNotValidException ex) {
        ProblemDetail problem = ProblemDetail.forStatus(400);
        problem.setTitle("请求参数无效");
        return ResponseEntity.badRequest().body(problem);
    }
}
\end{lstlisting}

异常处理器把可预期错误转换为稳定契约；意外异常只向客户端返回通用信息，详细堆栈写入受控日志。日志应包含请求标识、测站标识和事件类型，但不得记录密码、完整令牌或敏感个人信息。

\section{Spring Security 6与JWT}

认证回答“用户是谁”，授权回答“允许做什么”。Spring Security 6使用\texttt{@EnableMethodSecurity}启用方法授权，并采用Lambda DSL配置过滤链。无状态API关闭服务器会话并在JWT过滤器中建立认证上下文。

\label{lst:ch05-security-chain}
\begin{lstlisting}[language=Java,caption={Spring Security过滤链}]
@Configuration
@EnableMethodSecurity
class SecurityConfig {
    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http,
            JwtAuthenticationFilter jwtFilter) throws Exception {
        return http
            .csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(s -> s.sessionCreationPolicy(
                    SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(a -> a
                    .requestMatchers("/actuator/health", "/api/auth/**").permitAll()
                    .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}
\end{lstlisting}

浏览器若使用Cookie携带凭据，不能机械关闭CSRF防护；上例适用于只从Authorization头读取Bearer令牌的API。权限只使用一个枚举，避免名称和取值漂移。

\label{lst:ch05-jwt-filter}
\begin{lstlisting}[language=Java,caption={JWT认证过滤器}]
enum WaterSystemPermission {
    STATION_READ, READING_WRITE, ALERT_ACKNOWLEDGE
}

@Service
class AuthorizationService {
    void require(Authentication auth, WaterSystemPermission permission) {
        boolean granted = auth.getAuthorities().stream()
                .anyMatch(a -> a.getAuthority().equals(permission.name()));
        if (!granted) throw new AccessDeniedException("权限不足");
    }
}
\end{lstlisting}

JWT密钥通过配置注入并以足够长度的Base64值提供。jjwt 0.11+使用\texttt{parserBuilder()}；刷新令牌即使已过访问式过期点，也应先安全取得Claims，再验证令牌类型、签名、签发者和刷新期限。

\label{lst:ch05-kafka-listener}
\begin{lstlisting}[language=Java,caption={Kafka告警消费者}]
@ConfigurationProperties("security.jwt")
record JwtProperties(String secret, String issuer) {}

@Service
class JwtService {
    private final SecretKey key;
    private final JwtProperties properties;

    JwtService(JwtProperties properties) {
        this.properties = properties;
        this.key = Keys.hmacShaKeyFor(
                Decoders.BASE64.decode(properties.secret()));
    }

    Claims parseAllowExpired(String token) {
        try {
            return Jwts.parserBuilder().setSigningKey(key).build()
                    .parseClaimsJws(token).getBody();
        } catch (ExpiredJwtException ex) {
            return ex.getClaims();
        }
    }
}
\end{lstlisting}

刷新服务必须进一步确认Claims中的\texttt{type=refresh}、签发者和服务端撤销状态，才可签发新令牌对。配置常量由\texttt{JwtProperties}共享，不跨类访问私有常量。

\section{事务事件与消息队列}

同一应用进程内的领域事件可降低模块耦合。若处理必须在数据库事务成功后执行，应使用\texttt{@TransactionalEventListener}并指定\texttt{AFTER\_COMMIT}，不能用普通\texttt{@EventListener}声称“提交后执行”。

\label{lst:ch05-cache-service}
\begin{lstlisting}[language=Java,caption={缓存与分页查询}]
record ReadingSavedEvent(Long readingId, String stationId) {}

@Component
class ReadingEventHandler {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    void afterCommit(ReadingSavedEvent event) {
        metricsCounter.increment(event.stationId());
    }

    private final MetricsCounter metricsCounter;
    ReadingEventHandler(MetricsCounter metricsCounter) {
        this.metricsCounter = metricsCounter;
    }
}
\end{lstlisting}

跨服务通信必须使用网络可达的消息基础设施。下面的Kafka监听器位于告警服务，消费数据服务发布的事件；它不是进程内事件监听器。

\label{lst:ch05-metrics}
\begin{lstlisting}[language=Java,caption={运行指标记录}]
record ReadingMessage(String eventId, String stationId,
                      double level, Instant measuredAt) {}

@Component
class AlertMessageListener {
    private final AlertApplicationService alertService;

    AlertMessageListener(AlertApplicationService alertService) {
        this.alertService = alertService;
    }

    @KafkaListener(topics = "water.reading.saved", groupId = "alert-service")
    void onReading(ReadingMessage message) {
        alertService.evaluateIdempotently(message.eventId(), message.stationId(),
                message.level(), message.measuredAt());
    }
}
\end{lstlisting}

消息系统不能自动保证业务恰好执行一次。生产者应考虑事务外盒（outbox）或可靠发布；消费者用\texttt{eventId}去重，并配置有限重试、死信队列和监控。消息模式适合告警评估、通知和异步统计，不适合需要立即返回结果的简单查询。

在分布式部署中，服务发现负责把逻辑服务名解析为可用实例，配置中心负责管理环境参数，网关负责认证、限流与路由。Spring Boot应用应通过明确的Starter和配置文件接入这些基础设施，并在健康检查中验证注册状态、心跳超时和实例摘除；业务代码只依赖稳定的服务接口，不把具体注册中心的客户端注解扩散到领域层。这样的边界便于在开发、测试和生产环境切换实现。

\section{性能优化与可观测性}

性能优化先测量再修改。数据库查询应建立与查询模式匹配的索引并使用分页；热点且允许短暂陈旧的数据可缓存；外部调用设置连接、读取和总超时；线程池与数据库连接池容量应依据压测结果配置。

可观测性包括日志、指标和追踪。关键指标可包含请求延迟、错误率、数据库连接使用率、Kafka消费积压和告警处理时延。健康检查只说明实例可服务，不等同于业务正确。
