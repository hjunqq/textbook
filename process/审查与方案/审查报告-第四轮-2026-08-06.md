## 二、付印阻断项（P0，必须解决）

### R4-001【学术归属错误】第6章把陶飞等人的五维模型记为本教材原创

`chapter06.tex` 第246行原文：

> 陶飞、张萌的数字孪生车间模型包含物理空间、虚拟空间、服务系统和孪生数据\cite{tao2017dts}。**为便于水利平台设计，本教材把连接机制单独列为第五维**，形成 $DT=(PE,VE,Ss,DD,CN)$ …… **该五维写法是对原始构成的工程化展开**。

$(PE, VE, Ss, DD, CN)$ 正是陶飞等人 2019 年在《计算机集成制造系统》发表的《数字孪生五维模型及十大领域应用》中提出的原创模型（原文记为 $M_{DT}=(PE,VE,Ss,DD,CN)$）。`references.bib` 中只有 `tao2017dts`（IEEE Access 的车间四要素文章），**没有 2019 年五维模型文献**。教材把他人成果明文记为自己的扩展，是出版环节最敏感的一类问题。

修改：补入 2019 年文献条目，正文改为"在此基础上，陶飞等进一步提出数字孪生五维模型\cite{tao2019fivedim}……本章沿用该五维划分，并结合水利业务对各维度作工程化细化"，符号改为 $M_{DT}$。

### R4-002【自相矛盾且致习题无解】第6章 IFC 4.3 段落

> IFC 4.3新增Ports and Waterways Domain，覆盖水道、船闸、**闸门、溢洪道**等部分设施语义。**不能用**`IfcDoor`表示闸门、`IfcFurniture`表示廊道或把坝体简单当作`IfcStructuralMember`。同时必须说明标准边界：buildingSMART当前文档仍把**坝、堤、堰列为该域范围之外**。

### R4-003【代码会误导学生】第8章质量码与预警级的两处设计缺陷

`chapter08.tex` 第286–296行：

```java
public enum WarningLevel { BLUE, YELLOW, ORANGE, RED }
public WarningLevel classify(double score, String quality) {
    if (!"valid".equals(quality)) return WarningLevel.BLUE;   // ← 数据不可信 → 蓝色预警
    ...
    return WarningLevel.BLUE;                                  // ← 完全正常 → 也是蓝色预警
}
```

枚举里没有"无预警"状态（第259行为了统一口径把 `none` 删掉时，把"正常"这个业务态一并删了），于是 `score=0.01` 的正常测点和 `quality="suspect"` 的不可信数据都会被判成蓝色预警。28 个测点会持续产生蓝色告警风暴；更危险的是 `score=0.9 且 quality=suspect` 时系统吐出蓝色，掩盖了真实风险。这与第7章第44行"设备故障数据不得参与风险判定"、本章第326行"数据质量不足时应降低可信等级或停算"**正面冲突**。

同一节第224–245行 `inspect()`：缺测（`value==null`）与单位错误两个分支只往 `issues` 里加字符串，**没有改写 `quality`**，只有"范围越界"分支调了 `withQuality("suspect")`。结果是缺测记录带着原始 `valid` 质量码流向下游，被 `classify()` 当合格数据打分；第7章定义的 `missing` 质量码在整个第8章从未被写入过。

修改：枚举补 `NONE`；质量不合格返回"未评估"而非某个颜色（可用 `Optional` 或独立结果类型）；`inspect()` 对缺测写 `missing`、对单位错误写 `suspect` 或直接拒收，并明确多问题命中时的质量码优先级。

## 四、复核后排除的一条（不必修改）

上一轮审读中曾提出"习题用 `\item[\textbf{客观题}]` 分组会吃掉题号导致跳号"。**这个说法不成立。** LaTeX 的 `\@item` 只在**没有**可选参数时才执行 `\refstepcounter`，带可选参数的 `\item[...]` 不推进计数器。我用最小样例实测确认：

```
GroupA
1. first
2. second
GroupB
3. third
```

编号连续，无跳号。全书 14 处 `\item[...]` 分组写法可以保留。
